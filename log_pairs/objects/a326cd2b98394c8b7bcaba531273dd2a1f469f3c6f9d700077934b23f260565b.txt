# 코드 리뷰 가이드

## 1. 승인 기준
- 개발자 2명 승인이 필요합니다.
- `src/parkfee/pricing/`이나 `data/fee_schedules.json`이 바뀌면 서비스기획팀 1명이 추가로 승인합니다 (CODEOWNERS).

## 2. 리뷰어 체크리스트
- [ ] 규정 근거: 요금·할인 변경에 규정 문서와 조항이 연결되어 있는가
- [ ] 테스트: 규정 조항별 테스트와 경계값이 있는가, 순서가 틀리면 실패하는 숫자인가
- [ ] 금액: `Money` 밖에서 금액을 계산하지 않는가, 절사가 마지막 한 번뿐인가
- [ ] 구조: 계층 의존 규칙을 지키는가, 기존 정책 클래스를 고치지 않고 확장했는가
- [ ] 개인정보: 로그에 차량번호 전체가 없는가
- [ ] 문서: CLI·데이터 형식·ADR·변경 이력이 같이 바뀌었는가

## 3. 코멘트 규칙
- 접두어로 의도를 밝힙니다: `[필수]` 머지 전 반드시 수정, `[제안]` 선택, `[질문]` 확인 필요.
- 규정 해석이 갈리면 리뷰에서 결론 내지 말고 기획팀 담당자를 태그합니다.

## 4. 작성자 체크
- PR 설명에 재현 명령과 결과(JSON)를 붙입니다.
- 한 PR은 한 이슈만 다룹니다. 리팩터링과 기능 변경을 섞지 않습니다.
