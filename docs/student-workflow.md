# 수강생 진행 시나리오

## 1. 준비 확인과 참가자 등록

강사가 배정한 참가자 번호를 준비합니다. Codex CLI 로그인, GitHub collaborator 초대 수락과 Git 로그인은 수업 전에 마칩니다.

```bash
git clone https://github.com/legenduck/Architect-Practice-2.git
cd Architect-Practice-2
python lab.py doctor
python lab.py enroll p01
```

`p01`을 본인 번호로 바꿉니다. `doctor`가 모두 PASS이면 시작합니다. Git 작성자가 없으면 안내된 `git config user.name`과 `git config user.email`을 설정합니다. GitHub 쓰기 연결이 실패하면 초대 수락 여부와 Git 로그인을 확인합니다.

## 2. 제공된 지표로 관찰

```bash
python lab.py analyze
```

`output/report.html`을 브라우저로 열고 다음 순서로 확인합니다.

1. 과제 성공률: 네 최종 코드가 모두 통과했는데 이 값만으로 차이를 설명할 수 있는지 봅니다.
2. 정답 1개당 비용: 캐시 입력을 구분한 환산 비용이 어떻게 다른지 봅니다.
3. 작업 구간: 자료 확인·구현·금액 검증·검증 등의 입력 토큰과 시간을 봅니다.
4. 작업 기록 링크: 해당 요청을 펼쳐 메시지, 명령, 반환값과 전후 상태를 확인합니다.

자료는 재구성한 교육용 로그입니다. 토큰·시간은 모델값이며 실제 사용량·시간·청구액이 아닙니다. 구간 토큰에는 그 요청의 전체 입력이 포함되므로 문서나 도구 하나의 순수 비용으로 해석하지 않습니다.

## 3. 업무에 맞는 지표 만들기

예시 상황: 배포 전 자동 검증에서 이미 통과한 동일 조건의 검증을 반복하는지 확인하고 싶습니다.

```bash
python lab.py new-metric
codex
```

Codex에 다음처럼 요청합니다.

> docs/metric-design.md를 읽고 metrics/my_metric.json을 수정해 주세요. 평가 목적은 이미 통과한 동일 조건의 검증을 반복하는 비율을 확인하는 것입니다. same_state_passed_rechecks / test_runs를 백분율로 계산하고, 반복 검증이 필요했는지 수치만으로 단정할 수 없다는 한계도 적어 주세요. 원본 로그와 계산 도구는 수정하지 마세요.

이는 형식 예시입니다. 본인의 업무 목적에 맞춰 다른 재료와 기준을 선택해도 됩니다. 지표 파일을 수정했다면 Codex를 종료하고 적용합니다.

```bash
python lab.py analyze --metric metrics/my_metric.json
```

보고서를 새로 열어 '설계한 지표'를 확인합니다. 위 예시에서는 중복 처리 사례가 약 55.56%, 나머지는 0%입니다. 이것은 자료에 기록된 재검증 횟수의 차이이며, 지표의 타당성이나 특정 방식의 우수성을 자동으로 증명하지 않습니다.

## 4. 검토·수정·제출

다음 질문에 답할 수 있을 때 제출합니다.

- 무엇을 평가하며 담당 업무에서 왜 필요한가?
- 계산식의 분자·분모·단위는 무엇인가?
- 어떤 작업 차이가 드러났으며 로그의 어느 요청이 근거인가?
- 이 지표가 설명하지 못하는 부분은 무엇인가?

```bash
python lab.py submit
```

'제출 완료'의 브랜치·커밋을 확인합니다. GitHub에서 개인 브랜치의 `submissions/metric.json`을 볼 수 있습니다. 강사는 공통 자료로 결과를 다시 계산합니다. 공유 자료의 '계산 확인'은 계산 성공을 뜻하며 지표의 품질 점수가 아닙니다.

수정할 때는 지표 파일을 고친 후 `analyze --metric ...`과 `submit`을 반복합니다. 네트워크 실패 후에도 같은 제출 명령을 다시 실행하면 됩니다. 같은 내용을 다시 제출하면 새 커밋을 만들지 않습니다.

## 5. 다음에 이어 하기

같은 폴더에서는 그대로 지표를 수정하면 됩니다. 새 컴퓨터에서는 clone 후 동일한 번호로 `enroll`합니다. 기존 개인 브랜치와 마지막 제출한 지표 정의가 복원됩니다. 아직 제출하지 않은 수정은 원래 컴퓨터에만 있으므로 따로 보관하세요.

## 막혔을 때

| 증상 | 이어 가는 방법 |
|---|---|
| 기존 지표 파일이 있다는 메시지 | `new-metric` 대신 해당 파일을 수정 |
| 계산값이 미제공 | 보고서의 계산 상태 확인. 없는 값이나 0으로 나누는 식을 수정 |
| `retries`가 미제공 | 제공 자료에는 재시도 정의가 없음. 재검증 횟수와 혼동하지 말고 적절한 측정값 선택 |
| 참가자 미등록·브랜치 불일치 | 배정받은 번호로 `python lab.py enroll p01` 실행 |
| 제출 연결 실패 | `python lab.py doctor`로 로그인·권한·원격 브랜치 확인 |
| 다른 파일이 커밋 대상으로 지정됨 | `git status`로 확인 후 본인이 올리지 않을 파일만 stage에서 해제 |
| 자료 식별값 불일치 | 원본 자료를 수정했는지 확인하고 강사와 같은 자료로 다시 계산 |

`output/evaluation.json`에는 계산 결과와 자료 식별값이, `output/summary.csv`에는 기본 지표가 저장됩니다. `output/` 폴더 전체를 보관하면 연결된 로그 화면도 함께 열 수 있습니다.
