# 실습 데이터

현재 실제 실행 기록은 등록되지 않았습니다. 아래는 지표 계산에 사용할 데이터 항목과 해석 기준입니다.

## 비교할 실행 기록

같은 모델로 실습 1의 쿠폰 기능 추가 과제를 수행한 네 가지 작업 방식의 기록을 사용합니다.

| scenario 값 | 작업 방식 |
|---|---|
| context_overload | 입력 컨텍스트 과다 |
| repeated_work | 중복 전송과 재계산 |
| reasoning_reliance | LLM 추론에 대한 과도한 의존 |
| reference | 기법 적용 사례 |

## runs.jsonl

각 줄은 실행 한 건의 측정값입니다.

| 필드 | 의미 |
|---|---|
| id | 중복되지 않는 실행 ID |
| scenario | 위 네 가지 작업 방식 중 하나 |
| model | 사용한 모델 이름 |
| task_sha256 | 고정 과제 요청문의 식별값 |
| baseline_sha256 | 동일한 초기 코드를 사용했는지 확인할 식별값 |
| success | 공통 채점에 통과하면 true, 실패하면 false, 미확인이면 null |
| input_tokens | 실행의 전체 입력 토큰. 캐시 입력 포함 |
| cached_input_tokens | 입력 토큰 중 캐시 입력 부분. 알 수 없으면 null |
| output_tokens | 기록에서 확인한 전체 출력 토큰 |
| elapsed_seconds | 과제 실행 시간(초) |
| llm_calls | 확인 가능한 모델 호출 수. 완료 턴 수와 혼동하지 않음 |
| tool_calls | 정의된 범위에서 관측한 도구 호출 수 |
| retries | 정해진 기준에 따라 센 재시도 횟수. 기준은 measurement_notes에서 확인 |
| source_sha256 | 변환 전 측정 기록의 해시 |
| measurement_notes | 측정 범위와 제약 |

`null`은 값이 없다는 뜻이며 0과 다릅니다. 캐시 입력은 전체 입력 토큰에 이미 포함되어 있으므로 두 값을 더하지 않습니다. 이 기록은 쿠폰 기능 구현 과정의 측정값이며, 실습 중 지표 설계를 위해 사용하는 Codex 대화는 포함하지 않습니다.

## phases.jsonl

각 줄은 작업 구간 하나의 측정값입니다. `run_id`는 실행 ID, `id`는 구간 ID입니다. 구간별 입력 토큰, 출력 토큰과 시간은 각각 `input_tokens`, `output_tokens`, `elapsed_seconds`로 표시됩니다.

- `phase`: 문서 조회, 구현, 검증 등 실제 기록을 기준으로 정한 작업 구간 이름
- `evidence`: 원본 이벤트 번호나 관측 구간 등 수치의 근거
- `attribution_method`: 해당 구간에 자원을 배분한 기준

실행 총량 중 특정 구간에 배분되지 않은 값은 결과 화면에서 '미배분'으로 표시됩니다. 각 구간의 수치는 `evidence`와 `attribution_method`에 제시된 근거와 함께 해석합니다.

LLM 호출의 입력을 작업 구간에 배분한 수치는 해당 문서만의 순수 토큰 수와 다릅니다. 이전 문서가 이후 호출에도 포함될 수 있습니다. 도구 호출의 관측 시간이나 응답 대기 시간을 모델 내부의 추론 시간으로 바꾸어 표기하지 않습니다. 병렬로 겹치는 도구 실행 시간도 단순히 더해 전체 경과 시간처럼 사용하지 않습니다.

## pricing.json

`input_per_million`, `cached_input_per_million`, `output_per_million`은 각각 입력, 캐시 입력, 출력 100만 토큰당 단가입니다. 통화는 `currency`, 단가 출처는 `source`, 기준일은 `as_of`에서 확인합니다. 이 단가로 계산한 비용은 사내 실제 청구액이 아니라 동일한 기준으로 비교하기 위한 환산 비용입니다.

캐시 입력 단가가 다르지만 캐시 입력량을 모르는 경우 비용은 미제공으로 표시됩니다. `output_tokens`에 이미 포함된 추론 토큰을 다시 더하지 않습니다.

## 실행 내용 확인

`traces/실행ID.jsonl`은 명령과 이벤트를 추출한 표이며, `raw/실행ID.jsonl`은 원본 로그입니다. 결과 화면의 '실행 기록 확인'에서 추출 표를 살펴보고 원본을 열 수 있습니다. 지표값에 차이가 생긴 이유를 확인할 때 문서 조회, 테스트 실행과 수정 내용을 함께 살펴봅니다.
