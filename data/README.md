# 실습 데이터

현재 실제 실행 기록은 등록되지 않았습니다. `runs.jsonl`과 `phases.jsonl`은 비어 있으며, 숫자가 보이지 않는 것은 0으로 측정되었다는 의미가 아닙니다. 테스트 코드의 가상 값은 실습 데이터로 사용하지 않습니다.

## 필요한 기록

같은 모델로 실습 1의 쿠폰 기능 추가 과제를 수행한 네 가지 작업 방식의 기록을 사용합니다.

| scenario 값 | 수강생에게 표시할 이름 |
|---|---|
| context_overload | 입력 컨텍스트 과다 |
| repeated_work | 중복 전송과 재계산 |
| reasoning_reliance | LLM 추론에 대한 과도한 의존 |
| reference | 기법 적용 사례 |

실행 횟수는 사전 실행 결과를 보고 정합니다. 이 저장소는 특정 반복 횟수나 순위를 전제로 하지 않습니다. 실패 기록을 성공 기록으로 바꾸거나 누락된 수치를 임의로 채우지 않습니다.

## runs.jsonl

각 줄에 실행 한 건의 JSON 객체를 저장합니다.

| 필드 | 의미 |
|---|---|
| id | 중복되지 않는 실행 ID |
| scenario | 위 네 가지 작업 방식 중 하나 |
| model | 사용한 모델 이름 |
| task_sha256 | 고정 과제 요청문의 식별값 |
| baseline_sha256 | 동일한 초기 코드를 사용했는지 확인할 식별값 |
| success | 공통 채점에 통과하면 true, 실패하면 false, 미확인이면 null |
| input_tokens | 실행의 전체 입력 토큰. 캐시 입력 포함 |
| cached_input_tokens | 입력 토큰 중 캐시 입력 부분. 알 수 없으면 null |
| output_tokens | 기록에서 확인한 전체 출력 토큰 |
| elapsed_seconds | 과제 실행 시간(초) |
| llm_calls | 확인 가능한 모델 호출 수. 완료 턴 수와 혼동하지 않음 |
| tool_calls | 정의된 범위에서 관측한 도구 호출 수 |
| retries | 사전에 정의한 재시도 횟수. 재시도의 의미와 근거를 함께 기록 |
| source_sha256 | 변환 전 측정 기록의 해시 |
| measurement_notes | 측정 범위와 제약 |

없는 숫자는 `null`로 기록합니다. 입력 토큰과 캐시 입력을 더해서 총량을 만들지 않습니다. 지표를 만드는 수강생의 Codex 분석 대화는 이 기록에 합산하지 않습니다.

## phases.jsonl

각 줄에 작업 구간 하나를 기록합니다. `run_id`, 구간별 `id`, `phase`, `evidence`, `attribution_method`가 필요합니다. 측정된 `input_tokens`, `output_tokens`, `elapsed_seconds`를 추가합니다.

- `phase`: 문서 조회, 구현, 검증 등 실제 기록을 기준으로 정한 작업 구간 이름
- `evidence`: 원본 이벤트 번호나 관측 구간 등 수치의 근거
- `attribution_method`: 해당 구간에 자원을 배분한 기준

각 자원은 한 구간에만 배분합니다. 구간 합계가 실행 총량을 초과하면 검증 오류로 처리합니다. 분류하지 못한 값은 '미배분'으로 남깁니다.

LLM 호출의 입력을 작업 구간에 배분한 수치는 해당 문서만의 순수 토큰 수와 다릅니다. 이전 문서가 이후 호출에도 포함될 수 있습니다. 도구 호출의 관측 시간이나 응답 대기 시간을 모델 내부의 추론 시간으로 바꾸어 표기하지 않습니다. 병렬로 겹치는 도구 실행 시간도 단순히 더해 전체 경과 시간처럼 사용하지 않습니다.

## pricing.json

모델별 `input_per_million`, `cached_input_per_million`, `output_per_million`을 등록합니다. `currency`, `source`, `as_of`에 통화와 단가 출처, 기준일을 남깁니다. 사내 실제 청구액이 아니라 동일한 기준으로 비교하기 위한 환산 비용입니다.

캐시 입력 단가가 다르지만 캐시 입력량을 모르는 경우 비용을 계산하지 않습니다. `output_tokens`에 이미 포함된 추론 토큰을 다시 더하지 않습니다. 원본 사용량 형식의 정의를 사전 확인합니다.

## 기존 실습 1 기록 가져오기

```bash
python tools/import_practice1.py 실습1실행폴더 --scenario context_overload
```

실습 1의 `summary.json`과 `events.jsonl`을 읽어 숫자와 관측 범위를 변환합니다. 원본 로그 본문이나 인증 정보를 그대로 공개 저장소에 복사하지 않습니다. 변환 결과는 원본 해시로 연결하며, 원본 자료는 강사진이 별도로 보관합니다.

분석용 명령과 이벤트는 `traces/실행ID.jsonl`에 함께 저장합니다. 별도 채점 결과가 있다면 `--grade 채점결과.grade.json`을 지정합니다. 이 파일의 실행 ID와 소스 식별값을 원본 기록과 대조합니다.

배포할 원본 로그의 내용을 검토한 뒤 `--include-raw-log`를 추가하면 `raw/실행ID.jsonl`에 원본 사본도 저장합니다. 표로 추출된 명령만으로 판단하기 어려운 작업은 원본의 출력과 메시지를 확인합니다. 수업 자료 준비 검사에는 이 원본 사본도 포함됩니다.

이 변환만으로 구간별 수치와 재시도 의미를 확정할 수는 없습니다. 해당 기록은 근거를 확인해 추가해야 합니다. 이후 `python lab.py validate --require-ready`로 수업 자료의 준비 상태를 확인합니다.

준비 상태 검사는 필요한 항목의 존재와 형식을 확인합니다. 각 지표가 의미 있는 차이를 보여 주는지는 강사진의 사전 실행 검토가 필요합니다.
